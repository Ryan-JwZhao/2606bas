# BAS 使用说明

## 简介

BAS 是一个台球辅助系统，包含相机采集、目标检测、轨迹跟踪、状态机、路线规划和投影叠加等模块。

当前代码按模块拆分，便于单独排查：

- `bas/capture`：采集与相机接入
- `bas/perception`：检测与检测区域过滤
- `bas/tracking`：目标跟踪
- `bas/state`：状态机与回合判定
- `bas/planning`：规则路线、目标锁定、目标击球模式
- `bas/projection`：投影绘制与交互
- `bas/ui`：桌面控制台

## 基本使用

1. 安装依赖：运行 `Setup_Environment.cmd`
2. 启动桌面控制台：运行 `Start_BAS.cmd`
3. 直接用 Python 启动界面：`.\.venv\Scripts\python.exe -m bas ui`
4. 命令行无界面运行主流程：`.\.venv\Scripts\python.exe -m bas run --headless --max-frames 90`
5. 检查可用相机：`.\.venv\Scripts\python.exe -m bas probe-cameras`
6. 检查标定：`.\.venv\Scripts\python.exe -m bas inspect-calib`

## 目标击球模式

目标击球模式位于“设置 -> 路线策略 -> 目标击球模式”，现在按真实时间工作，不再直接按帧数工作。

关键参数：

- `首次激活保持(秒)`：稳定指向同一颗非白球多久后进入目标击球模式。默认 `1.0`
- `改锁保持(秒)`：已经激活后，明确指向另一颗球多久后才切换。默认 `1.5`
- `短暂丢帧容忍(秒)`：中间短暂丢杆、抖动、识别成白球时，允许保留累计进度多久。默认 `0.2`
- `释放确认(秒)`：状态机进入出杆相关阶段后，连续保持多久才真正退出目标击球模式。默认 `0.3`

状态文本会直接显示毫秒进度，例如：

- `activate_pending 620/1000ms`
- `switch_pending 840/1500ms`
- `release_pending 150/300ms`

这样可以直接判断是“还没累计够”，还是“中途被重置/进入释放确认”。

## 为什么旧版 10 帧会实测成 3 秒

旧版逻辑的“10 帧”不是屏幕刷新 10 帧，而是“同一颗非白球连续被识别成当前指向目标 10 次”。

只要中间任意一次出现下面任一情况，计数就会被清空重新开始：

- 这一帧没识别到有效球杆方向
- 这一帧识别成白球
- 这一帧识别成另一颗目标球

同时，运行频率还会受到这些因素影响：

- `detect_fps_limit_hz`
- 检测缓存帧
- 球杆边缘检测稳定性
- 光照、反光、球杆纹理

所以旧版把设置改成 `10`，并不等于“稳定 10 个屏幕帧就能进模式”，现场体感上完全可能拉长到 3 秒以上。

## 调参建议

- 想更快进入目标击球模式：优先减小 `首次激活保持(秒)`
- 想减少临门一脚误切球：增大 `改锁保持(秒)`
- 想减少轻微抖动掉锁：增大 `短暂丢帧容忍(秒)`
- 想减少刚出杆前被瞬时误释放：增大 `释放确认(秒)`

推荐起点：

- 首次激活：`1.0`
- 改锁保持：`1.5`
- 丢帧容忍：`0.2`
- 释放确认：`0.3`

## 常用排查项

- 目标模式进入仍然很慢：先看“性能”日志里的 `fps`、`det`、`cache`，再看 `detect_fps_limit_hz` 是否过低
- 目标模式经常误切到别的球：先增大 `改锁保持(秒)`，再检查球杆方向识别是否稳定
- 目标模式刚进就掉：先看状态文本是否变成 `release_pending ...`，如果是，说明更像状态机误触发释放
- 预览画面抖动大：优先检查检测模型、曝光、白平衡、球杆高光和台布反光
